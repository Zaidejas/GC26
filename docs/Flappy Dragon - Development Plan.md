# План разработки: Flappy Dragon (Unity, Android)

**Бюджет времени:** 13 недель × 20 ч ≈ **260 часов**. Для новичка этого хватит на небольшую законченную игру, если держать объём под контролем. Главное правило: **сначала игра работает на квадратиках, потом становится красивой.**

---

## 0. Решения до старта

**Стиль: пиксель-арт, а не чиби.**
- Пиксельные спрайты маленькие, и даже простой рисунок в них выглядит цельно.
- Чиби требует хорошего навыка рисования. Если генерировать его через ИИ, персонаж выходит каждый раз немного другим, особенно в кадрах анимации.
- Для пиксель-арта есть много бесплатных и дешёвых наборов на itch.io. Их можно взять за основу и доработать.

**Инструменты:**

| Задача | Инструмент |
|---|---|
| Движок | Unity 6 LTS + модуль **Android Build Support** |
| Код | Visual Studio / VS Code / Rider + ИИ-ассистент (Claude Code, Cursor и т.п.) |
| Резервные копии | **Git + GitHub Desktop** (обязательно, см. раздел о вайб-кодинге) |
| Пиксель-арт | Aseprite (платный) или бесплатные LibreSprite / Piskel |
| Звуки | jsfxr / ChipTone (генераторы 8-битных эффектов), freesound.org |
| Анимации интерфейса | DOTween (бесплатная версия) |
| Задачи | Trello / Notion: колонки «Нужно / В работе / Готово» |

**Ритм:** например, 4 дня по 5 часов или 5 дней по 4 часа. Внутри недели примерно так: **12 ч на разработку, 4 ч на учёбу, 4 ч на арт и звук.**

## 1. Дизайн механик (коротко)

- **Основа:** тап, и дракон взмахивает крыльями. Работает гравитация. Препятствия — сталактиты сверху и сталагмиты снизу — едут справа налево. Пролетел сквозь проход — получил +1 очко.
- **Бесконечная генерация:** новые препятствия появляются за правым краем экрана, ушедшие за левый край возвращаются в пул и используются снова.
- **Жизни:** 3 сердца. После удара дракон 1,5 с неуязвим и мигает. Иногда встречается сердце-подбор.
- **Ускорение (огненный рывок):** шкала в нижней полосе экрана заполняется от собранных огоньков. Когда она полная, загорается отдельная кнопка рывка внизу; игрок сам решает, когда её нажать. Рывок на 2 с: скорость растёт, дракон неуязвим и разбивает препятствия с частицами.
- **Сложность:** Лёгкая / Средняя / Сложная. Это просто разные числа: скорость, ширина прохода, частота препятствий. Хранятся в **ScriptableObject**.
- **Уровни:** бесконечный режим, разбитый на «этапы». Каждые N очков начинается новый этап: игра ускоряется, проходы сужаются, появляется плашка «Этап 2».
- **Атмосфера:** одна постоянная тема — рассвет в скалистом ущелье. Смены дня и ночи нет; живость дают параллакс, облака и пыль в лучах солнца.
- **Экран:** игровое поле 3:4 по центру, сверху и снизу чёрные полосы. Вверху сложность, очки, пауза; внизу сердца, шкала ускорения, кнопка рывка.
- **Анимации:** только 2D, но плавные — больше кадров и движения кодом (наклон, покачивание, сжатие при взмахе).

**Скрипты, которые понадобятся** (это «карта» для ИИ):
`GameManager` (состояния: меню / игра / пауза / конец), `DragonController`, `ObstacleSpawner` + `Obstacle` (с пулом объектов), `ScoreManager`, `LivesSystem`, `DashAbility`, `Pickup`, `DifficultySettings` (ScriptableObject), `StageManager`, `DawnBackground`, `ParallaxLayer`, `LetterboxCamera`, `UIManager`, `AudioManager`, `SaveSystem` (PlayerPrefs).

## 2. Понедельный план

### Месяц 1: фундамент и играбельный прототип

**Неделя 1. Установка и основы**
- [ ] Установить Unity Hub, Unity 6 LTS с модулем Android, редактор кода, Git и GitHub Desktop.
- [ ] Пройти часть Unity Learn → *Unity Essentials* и основы C#: переменные, методы, `if`, классы, `Update`.
- [ ] **Сразу собрать пустую сцену на свой телефон.** Сборка под Android — самое частое место, где новички застревают, поэтому проверьте его в первую неделю.
- ✅ Готово, если: на телефоне открывается ваше «приложение» с цветным фоном.

**Неделя 2. Основная механика**
- [ ] Дракон-квадрат: Rigidbody2D, прыжок по тапу.
- [ ] Препятствия-прямоугольники движутся влево, спавнер создаёт их со случайной высотой прохода.
- [ ] Столкновение → конец игры → перезапуск.
- ✅ Готово, если: можно играть во «Flappy Bird из квадратиков».

**Неделя 3. Игровой цикл и интерфейс**
- [ ] Счёт, рекорд (PlayerPrefs), стартовое меню, экран проигрыша, пауза.
- [ ] GameManager с состояниями.
- [ ] Пул объектов вместо Instantiate/Destroy: на нём держится бесконечная генерация сталактитов и сталагмитов.
- [ ] Поле 3:4 и чёрные полосы сверху и снизу (`LetterboxCamera`), интерфейс в полосах.
- ✅ Готово, если: есть полный цикл «меню → игра → проигрыш → снова».

**Неделя 4. Ощущение от управления + арт-направление**
- [ ] Настроить гравитацию, силу прыжка и наклон дракона. Это 80% того, насколько игра «цепляет».
- [ ] Собрать доску референсов, выбрать палитру (например, с lospec.com), нарисовать первый эскиз дракона 32×32 или 48×48.
- [ ] Навести порядок в коде, всё закоммитить.
- 🏁 **Веха 1:** играбельный прототип на телефоне. Дайте поиграть 2–3 друзьям.

### Месяц 2: фичи (графика пока временная)

**Неделя 5. Жизни**
- [ ] 3 жизни, неуязвимость после удара, мигание, тряска экрана, сердечки в интерфейсе, подбор сердца.

**Неделя 6. Рывок**
- [ ] Огоньки, шкала ускорения в нижней полосе, кнопка рывка (загорается при полной шкале), неуязвимость, разрушение препятствий с частицами и «ударом».

**Неделя 7. Сложность и этапы**
- [ ] ScriptableObject для трёх уровней сложности и выбор в меню.
- [ ] StageManager: каждые N очков усложнение и плашка «Этап X».
- [ ] Отдельный рекорд для каждой сложности.

**Неделя 8. Рассветный фон**
- [ ] Рассветное небо (градиент от розово-оранжевого к голубому), 3–4 слоя параллакса (небо, дальние скалы, ближние скалы, облака).
- [ ] Плывущие облака и пыль в лучах солнца. Смены дня и ночи нет.
- 🏁 **Веха 2:** все механики готовы. В этот момент **заморозьте список фич**: новое больше не добавляем.
- 📌 Зарегистрируйте аккаунт разработчика Google Play ($25, проверка личности может занять несколько дней).

### Месяц 3: красота, звук, Android, релиз

**Неделя 9. Арт**
- [ ] Плавные 2D-анимации дракона: взмах (8 кадров), удар, рывок + наклон и сжатие кодом.
- [ ] Препятствия: сталактиты и сталагмиты, 3–4 варианта формы.
- [ ] Рассветные фоны, огоньки, сердца, иконки интерфейса, пиксельный шрифт.

**Неделя 10. Звук + «сочность» + первый тестовый билд**
- [ ] Средневековая чиптюн-музыка (лицензия CC0 или CC-BY), звуки взмаха, огонька, удара, рывка, проигрыша.
- [ ] Частицы, анимации интерфейса через DOTween, настройки звука.
- [ ] ⚠️ **Загрузить билд в закрытое тестирование Google Play.** Новые личные аккаунты должны провести закрытый тест **минимум с 12 тестировщиками в течение 14 дней**, иначе не дадут выпустить игру.

**Неделя 11. Оптимизация под Android**
- [ ] Стабильные 60 FPS, разные соотношения сторон и безопасная зона (вырезы экрана).
- [ ] Иконка, сплэш-экран, сборка AAB, keystore. **Сохраните keystore и пароль в двух местах**: без них игру нельзя будет обновить.

**Неделя 12. Плейтест и баги**
- [ ] Собрать отзывы тестировщиков, исправить ошибки, поправить баланс (сложность первых 30 секунд особенно важна).

**Неделя 13. Запас и релиз**
- [ ] Страница в магазине: скриншоты, описание, короткое видео или GIF.
- [ ] Публикация в Google Play (или на itch.io как запасной вариант). Подведение итогов: что получилось, что нет.

## 3. Как правильно «вайб-кодить» новичку

1. **Одна задача — один запрос.** Не «сделай мне игру», а «напиши скрипт DragonController: прыжок по тапу, Rigidbody2D, наклон по скорости».
2. **Давайте контекст.** Пример запроса:
   > «Unity 6, 2D, C#. У меня есть GameManager с состояниями Menu/Playing/GameOver. Напиши LivesSystem: 3 жизни, после удара 1,5 с неуязвимости с миганием спрайта, событие OnLivesChanged для UI. Объясни, куда повесить скрипт и что настроить в инспекторе.»
3. **Просите объяснить код** построчно, хотя бы поначалу. Без понимания на 2-м месяце проект станет неуправляемым.
4. **Коммит в Git после каждого рабочего шага.** Если ИИ всё сломал, откатываетесь за 10 секунд.
5. **ИИ ошибается в API Unity.** Он может предложить устаревшее: например, в Unity 6 вместо `rigidbody.velocity` используется `linearVelocity`, а вместо старого `Input.GetMouseButtonDown` лучше новый Input System. Если есть ошибка в консоли, копируйте её текст ИИ целиком.
6. **Не давайте ИИ переписывать весь проект.** Просите менять конкретный скрипт и конкретный метод.
7. **Цифры баланса держите в инспекторе** (`[SerializeField]`) или ScriptableObject, а не в коде.

## 4. Риски и что резать

**Если отстаёте, режьте в таком порядке:**
1. Падающие камни с этапа 5
2. Подборы сердец (жизни остаются)
3. Подвижные сталактиты
4. Анимации интерфейса

**Не режьте никогда:** ощущение от управления, рассветную атмосферу, три сложности, поле 3:4 с полосами, звук, работу на телефоне.

**Если успеваете:** скины драконов за огоньки, достижения и таблица лидеров через Google Play Games, ежедневные задания.

**Главные риски для новичка:** сборка под Android (проверяем в 1-ю неделю), разрастание фич (заморозка после 8-й недели) и 14-дневный закрытый тест Google Play (начинаем на 10-й неделе).
